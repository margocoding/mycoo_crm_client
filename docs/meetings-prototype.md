# Прототип встреч

Раздел `/dashboard/calls` содержит интерактивный фронтенд для проверки сценариев встреч. Использует существующую авторизацию и оболочку кабинета. Реальные звонки и интеграция с Контур Толк в этот этап не входят.

## Сценарии

- Список, поиск, фильтры по статусу и департаменту; быстрый звонок.
- Создание, редактирование и отмена запланированной встречи: название, дата, длительность, департамент, участники, повестка и настройки входа.
- Перед входом — демонстрация состояний микрофона и камеры, выбор роли для проверки интерфейса.
- В комнате — плитки участников, закрепление плитки, локальный чат, поднятая рука, показ повестки вместо экрана, индикатор демозаписи, зал ожидания и управление участниками.
- Выход с возможностью вернуться; завершение для всех; сохранение ручных заметок после завершения.

## Роли встречи

| Действие | Организатор | Соорганизатор | Участник |
| --- | --- | --- | --- |
| Свой микрофон, камера, рука, чат | Да | Да | Да |
| Демонстрация экрана | Да | Да | Если разрешена |
| Допуск из зала ожидания | Да | Да | Нет |
| Выключение чужих микрофонов | Да | Да | Нет |
| Удаление из комнаты | Кроме себя | Только обычных участников | Нет |
| Смена ролей, настройки входа | Да | Нет | Нет |
| Завершение для всех | Да | Нет | Нет |

Роли встречи не меняют роли в компании. Переключатель «Войти как» проверяет только демонстрационный интерфейс и не предоставляет доступ к данным других пользователей.

## Данные и ограничения

Тестовый справочник вынесен в `src/data/meetings/prototypeData.ts`. Настоящие сотрудники и департаменты с сервера пока не загружаются. Состояние встреч сохраняется в `localStorage` под версионированным ключом, отдельно для каждой пары workspace/user. Локальный просмотр использует отдельный ключ.

Название, даты, состав, роли, статус и заметки переживают перезагрузку. Чат, допуск/удаление участников, микрофоны, камера, блокировка входа, демонстрация и запись действуют только в текущей демосессии. При повторном входе комната инициализируется заново из карточки встречи. Блокировка входа показывает состояние интерфейса: сетевых подключений в прототипе нет.

Демоссылка открывает карточку только в том же браузере и контексте пользователя. Приглашения, email и сообщения другим людям не отправляются. Устройства не запрашиваются, аудио/видео и экран не захватываются, файлы записи не создаются. Протоколы и задачи через ИИ не генерируются.

## Локальная проверка

```sh
npm run dev -- --host 127.0.0.1 --port 4190
npm run typecheck
npm run build
```

Для просмотра без запущенного API: `http://127.0.0.1:4190/preview/meetings`. Этот маршрут доступен только в режиме разработки; production-сборка его исключает. В кабинете раздел остаётся по `/dashboard/calls`.

Основной ручной сценарий: создать встречу, изменить департамент и роли, перезагрузить карточку, войти разными ролями, допустить/удалить участника, отправить локальное сообщение, выйти и вернуться, завершить встречу организатором, сохранить заметки. Отдельно проверить отмену, фильтры, отсутствие встречи по ссылке и мобильную ширину.

Проверка навигации: открыть карточку встречи одного отдела, вернуться в список, войти в другую встречу под её участником, дважды нажать «Назад» в браузере и затем «Вперёд». Должны открываться соответствующие карточки без переноса роли и состояния комнаты. Состояние входа, комнаты и редактирования хранится в `MeetingSession`, который создаётся заново при смене встречи.

## Следующий этап

При подключении микросервиса заменить локальное хранилище и демосостояние комнаты на его API/SDK, справочник — на данные команды. Авторизацию, доступ к департаментам и все права управления проверять на сервере; текущие клиентские проверки служат прототипу. Запись, транскрипцию и обработку протоколов основным backend подключать отдельно после согласования контракта сервиса.
