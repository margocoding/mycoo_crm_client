# Партнёрская программа: интерактивный прототип

## Страницы

- `/partner` — лендинг, пример расчёта комиссии и условия.
- `/partner/register` — регистрация партнёра с немедленным доступом к кабинету и ссылке. Имя и email обязательны, компания необязательна. Старый адрес `/partner/apply` перенаправляет сюда.
- `/partner/account` — обзор, ссылка, баланс и последние операции.
- `/partner/account/referrals` — компании, оплаты и начисления.
- `/partner/account/payouts` — запрос выплаты и история с сохранёнными реквизитами.
- `/partner/account/details` — реквизиты получателя.
- `/admin` — очередь выплат; `/admin/partners` — реестр зарегистрированных партнёров.
- `/admin/ledger` — журнал, тестовые оплаты, возвраты и корректировки.
- `/admin/settings` — условия программы и смена логина/пароля.

Начальный демо-доступ: `admin` / `admin`. Сброс для повторной проверки: удалить только ключи `mycoo.partner-demo.v1.*` в хранилище этого сайта и перезагрузить страницу. Переключатель «Партнёр» показывает разные профили.

Участвовать может любой человек: заявки на партнёрство, модерация и одобрение профиля отсутствуют. Сохранённые профили из первой версии автоматически переходят на новые правила; идентификаторы, ссылки, начисления, реквизиты и выплаты сохраняются. Проверка заявок на **вывод средств** остаётся.

## Демонстрационные условия

20% с оплат в течение 12 месяцев после регистрации клиента, 14 дней проверки, минимальная выплата 5 000 ₽. Условия редактируются в админке; это не утверждённая оферта. Изменения применяются к последующим оплатам, существующие записи журнала сохраняются.

## Граница прототипа

Данные сохраняются только в этом браузере в ключах `mycoo.partner-demo.v1.*`. Проверка входа и пароль администратора также локальные; это демонстрация формы, а не серверная авторизация. Для проверки используйте вымышленные данные. В разных браузерах независимые примеры; совместная работа в нескольких вкладках не поддерживается.

Реальные регистрации по партнёрской ссылке, начисления от платёжной системы, переводы денег, письма и серверные права доступа не подключены. Ссылка использует отдельный параметр `partner`; существующая программа скидок `ref` не меняется. Запросов в CRM API на этих страницах нет.

Журнал показывает связь с оплатой, исключает повторный ID платежа и фиксирует возврат/корректировку отдельной записью. Заявки резервируют баланс, отклонение освобождает резерв, выплата учитывает фактическую сумму и дату. Все операции имитируются локально. При подключении бэкенда эти проверки и неизменяемость истории должны обеспечиваться на сервере и в транзакциях БД.

## Проверки

`npm run typecheck`, `npm test`, `npm run build`. Тесты прототипа покрывают регистрацию, перенос старых профилей, расчёт баланса, резервирование, возвраты, повторные платежи, смену условий, локальный вход и восстановление данных. Для ручной проверки: регистрация с именем и email → кабинет со ссылкой; запрос выплаты → проверка → одобрение → фиксация выплаты.
