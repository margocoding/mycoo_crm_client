# Партнёрская программа

## Страницы и доступ

- `/partner` — условия с сервера и калькулятор комиссии.
- `/partner/login` — вход или регистрация через существующий аккаунт MyCoo: email, код из письма и пароль.
- `/partner/register` — имя и компания партнёра. Email берётся из подтверждённого аккаунта. Профиль и ссылка доступны без одобрения; платная подписка для участия не нужна.
- `/partner/account` — собственный баланс и ссылка; `/referrals`, `/payouts`, `/details` внутри этого пути — привлечённые клиенты, выплаты и реквизиты.
- `/admin/login` — отдельная серверная сессия администратора; `/admin` — заявки на выплату.
- `/admin/partners`, `/admin/ledger`, `/admin/settings` — реестр, сверка оплат/возвратов/корректировок, условия и смена доступа.

## Данные

Интерфейс обращается к `/partners/*` и `/partner-admin/*` по `VITE_API_URL`. Партнёр получает только собственные записи. Финансовые изменения, права, уникальность платежей, резервирование и история обеспечиваются API и БД.

Демонстрационные профили, локальные балансы и пароль `admin/admin` больше не используются и не переносятся в настоящую БД. Администратор создаётся командой на бэкенде; его токен хранится в `sessionStorage` отдельно от CRM. В браузере также сохраняются непрозрачные ключи незавершённых операций, чтобы повторить запрос после потери ответа без двойного начисления/списания. Денежные снимки и реквизиты не сохраняются в хранилище браузера.

Любой финансовый запрос блокирует повторное нажатие до результата. После записи кабинет обновляет данные с сервера. Сетевые ошибки показываются явно; подстановка демонстрационных значений отсутствует. Переход между партнёрским кабинетом и админкой очищает предыдущий набор данных.

Начальные условия остаются предварительными: 20%, первые 12 месяцев, 14 дней удержания, минимум 5 000 ₽; редактируются в админке. Экран фиксации выплаты записывает результат перевода, выполненного администратором, и сам деньги не переводит. Ручная запись оплаты используется для сверки подтверждённой операции.

## Проверки

`npm run typecheck`, `npm test`, `npm run build`. Фронтенд-тесты проверяют отображение баланса по журналу и сохранение ключа при повторе неизвестного результата. Финансовые инварианты и права проверяются на бэкенде.

Ручной сценарий: создать аккаунт с подтверждением email → зарегистрировать партнёра → открыть ссылку в другом аккаунте и зарегистрировать клиента → подтвердить его оплату → дождаться/на тестовом окружении снять удержание → заполнить реквизиты → запросить выплату → проверить и одобрить в админке → зафиксировать фактическую сумму и дату → проверить кабинет после перезагрузки.
